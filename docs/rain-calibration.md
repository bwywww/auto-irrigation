# 雨水保护与灌溉标定

雨水保护已写入Nano和网页。当前使用[综合灌溉算法](irrigation-algorithm.md)，湿度30%触发、45%结束补水，温度和昼夜微调每轮2～20秒时长。本文后半部分的物理水量模型是后续标定方案，不是当前执行公式。

## 1. 接线与首次校准

断电接线，使用5V雨水模块：

| 模块接口 | Nano |
|---|---|
| VCC | 5V |
| GND | GND |
| 模拟输出AO | A3 |

当前已采用参考测量值：干燥ADC=0，沾湿400以上，可超过600。`Config.h` 已设置 `RAIN_CONFIGURED=true`、`RAIN_DRY_RAW=0`、`RAIN_WET_RAW=400`，400是湿参考值，不是上限。

1. 上传 `firmware/smart_irrigation/smart_irrigation.ino`，刷新新版网页并连接；不需要再次修改配置开关。
2. 保持探头干燥，等待上电后的60秒确认完成。主页显示“未下雨”；土壤与执行器检查也通过后，允许启用自动或手动。
3. 先以5秒手动浇水检查继电器测试灯，再在开启期间滴水，主页应显示“下雨”且输出关闭。
4. 擦干后保持60秒；期间再湿会重新计时。手动不会自动恢复，自动仍需满足湿度和冷却条件。
5. 在“设置→采集诊断”复核雨水ADC与环境变化。以后更换探头时可先设RAIN_CONFIGURED=false重新测量，再填写端点、启用并上传。

当前触发值为ADC≥80；整数换算下，ADC≤43开始累计干燥时间（理想10%位置为40）。这是以0/400参考端点和20/10阈值计算的初始灵敏度，不是已完成现场优化的阈值。44～79之间：先前已确认干燥时保持允许；先前有雨时仍限制，干燥计时重置。现场重点观察少量水滴能否可靠触发、干燥时是否误报。

湿润程度按 `R=clamp(100×(ADC−干值)/(湿值−干值),0,100)` 换算。整数换算后R≥20触发停水，R≤10才累计干燥时间，避免边界反复跳动。阈值是相对于两个实测端点的探测板湿润程度，**不是降雨概率或毫米雨量**。需用实际小水滴检验灵敏度，必要时调整20/10并保持干阈值小于湿阈值。

每250ms进行一次8次平均采样；检测到湿后直接由Nano关闭输出，不等待蓝牙或网页。干燥确认中R>10重置60秒计时，达到20则重新显示有雨；已经确认干燥后，只有达到20才重新阻断。上电、采样过期恢复后也需要重新确认60秒。

0和1023可以是模块的真实输出端点，不能一律视为断线。三线模拟模块的断线或卡死输出可能看起来像干燥，软件不能识别所有硬件失效。当前“采样异常”覆盖配置错误、非法数值及采样过期，不等于完整断线检测。

## 2. 用继电器测试灯验证

继续使用已验证接法的继电器测试LED，D6另作状态指示。先完成上述校准，再按顺序测试：

| 测试 | 应观察到的结果 |
|---|---|
| 手动浇水期间滴水 | 测试灯熄灭，输出关闭，网页显示雨水限制 |
| 湿探头时再次开始 | 禁止开启，复位也不能绕过雨水限制 |
| 擦干并保持60秒 | 限制解除；手动保持关闭，需要新浇水指令 |
| 倒计时中再次滴水 | 重新变湿，下次干燥重新计满60秒 |
| 自动模式浇水期间滴水 | 关闭但保留自动模式，开始5分钟自动冷却 |
| 自动模式雨水限制解除 | 只有湿度≤启动值且冷却结束才重新启动 |
| 关闭网页后滴水 | Nano仍执行雨水保护；自动不依赖网页在线 |
| 急停后擦干 | 不自动解除急停，仍需满足检查条件并显式复位 |

例如开阀后遇雨关闭，1分钟后确认干燥，此时自动冷却通常还剩约4分钟。60秒负责确认探头已干，5分钟负责避免土壤渗水尚未稳定时反复启动，两者分别计时。

雨水限制、未校准或采样异常时D6快闪。限制解除后按原状态显示：待机灭、监测慢闪、浇水常亮；其他故障的快闪优先。

网页记录雨水状态变化事件，每条新样本保存雨水ADC、状态和剩余确认时间；CSV追加这三列。原IndexedDB数据库不变，旧记录没有雨水字段，其导出列留空，不推断为无雨。

## 3. 更精确的灌溉时间：先标定水量

现有湿度是700/400端点之间的相对百分比，不能直接当成土壤体积含水率。提高精度首先需要实测流量及土壤响应。雨水探头只能作为停水条件，不能根据板面湿润程度计算有效降雨量。

有体积含水率标定时，可以按根区缺水量计算：

```text
V净(L) = 1000 × A × Z × max(0, θ目标 − θ当前)
t总(s) = V净 / (η × Q)
```

- A：实际灌溉面积，m²；Z：有效根区深度，m。
- θ：标定后的体积含水率，用0～1小数；不能直接代入本项目湿度%除以100。
- Q：实际工作压力下的出水流量，L/s；用量杯测“收集体积÷开启秒数”，重复测量。
- η：灌溉有效利用率，0～1，需结合滴灌、径流和排水情况确定。

该式由“土壤体积×含水率缺口”换算成升，再以有效流量换算秒数。土壤、根区深度与灌溉效率对水量的影响可参考[FAO灌溉调度说明](https://www.fao.org/4/t7202e/t7202e06.htm)。

算出的总时间不能直接连续执行。建议采用“短时灌溉→等待渗透→重新采样”的方式，并保留当前雨水、急停、故障与60秒连续上限。示例参数A=0.5m²、Z=0.15m、θ从0.20补至0.24、η=0.9、Q=0.05L/s，得到净水量3L、总时间约66.7秒；这已经超过当前连续上限，必须分次并重新评估，不能一次开启67秒。以上数值仅用于解释单位，不是本项目的实测设置。

暂时没有体积含水率标定时，可以先建立局部经验关系：

```text
g = 多次试验的中位数[(渗透稳定后湿度% − 浇水前湿度%) / 实际水量L]
t脉冲 = min(α × max(0, M目标 − M当前) / (g × Q), 单次时间上限)
```

g单位为“百分点/L”，Q单位为L/s；需在相同土壤、探头位置、供水位置和相近湿度区间测量。至少重复3次，在关闭输出、渗透稳定后取值，排除变化低于噪声、饱和或负响应的试验。α用于少量分次补水，例如0.25可作为受控试验起点，不能宣称普遍最优。g随土壤状态变化，试验无可靠正响应时禁止用该公式外推。

以上两种方案都必须先检查雨水：未校准、有雨、等待干燥或采样异常时，本次灌溉时间为0。还应标定单次及累计水量限制；当前代码没有累计水量控制；已执行的是综合灌溉算法文档中的经验分轮控制，不是这里依赖流量标定的水量公式。

## 4. 温度和光照如何参与

当前土壤读数已经反映此前蒸发与吸水造成的变化。直接因温度高、光照强再乘一个放大系数，可能重复补偿，并不能保证更精确。

有充分数据后，可用气象条件预测下一时段耗水，用于决定何时检查或补水。标准参考蒸散计算还需要空气湿度、风速和辐射等输入；当前仅有温度与估算lux，条件不足。lux也不能未经标定直接替代太阳辐射。参见[FAO参考蒸散方法与输入要求](https://www.fao.org/4/x0490e/x0490e05.htm)。

本阶段温度修正限制在±20%、昼夜修正为±10%，均为试验初值，不能宣称比湿度单独控制更节水或更精确；后续需测Q和土壤响应验证、调整系数。
